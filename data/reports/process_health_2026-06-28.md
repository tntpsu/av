## TOP 3 PROCESS IMPROVEMENTS

```
════════════════════════════════════════════════════════════════════════
1. Physics-first design review gate

   Pattern: 4/9 design issues (44%) are proxy approximations — a
            speed table where physics gives sqrt(8R×e), a threshold
            pair where κ×v² gives the joint constraint, a scalar
            collapse where a spatial profile is the right structure.

   Action: Before accepting any new parameter or threshold, require a
           one-line answer: "What physical quantity does this
           approximate, and why can't we compute it directly?" Add
           this as a design-review checklist item in CLAUDE.md.
           (Constraint already in CLAUDE.md Key Constraints #8 but
           it's not enforced at code-review time.)

   Impact: Prevents the proxy class outright. The 4 proxy-approx
           issues cost an estimated 14 total detection iterations and
           multiple multi-run A/B test cycles.

2. Mandatory E2E gate for any numeric constant change in tuning files

   Pattern: The single highest-cost event (entry 13, +82.5 pts
            recovered) was a 2-line undocumented tuning change
            bundled into a feature commit. Detection took only 1
            iteration but only because /iterate bisected it; without
            bisection it could have persisted.

   Action: Any diff touching av_stack_config.yaml, MPC weight params,
           or per-track overlays requires an E2E validation record in
           the commit message (minimum 60s run on highway_65 + one
           curve-heavy track). Grep hook in SCRIPT_RUNBOOK.md to
           surface the requirement.

   Impact: The q_lat regression was caught in 1 iteration; the issue
           is that it merged at all. A lightweight syntactic gate
           (does this commit change a numeric constant in a tuning
           file without an E2E marker?) costs 0 iterations.

3. Phase/signal isolation checklist in steering term code review

   Pattern: 3 implementation issues share the same root: a steering
            term computed for one phase leaked into another (term_time
            on straights, Stanley during braking, PP return-path
            no-blend). All were found by steering decomposition traces
            after the fact.

   Action: Add a code-review rule: any new or modified steering term
           must explicitly name its active phase(s) in a short inline
           comment, and a test must assert it is zero outside those
           phases. The steering decomposition trace tool can generate
           the test case from a golden recording.

   Impact: Would have caught the term_time leak and regime blend
           asymmetry at review time (0 iterations) vs 1–2 iterations
           post-merge.
```
