## TOP 3 PROCESS IMPROVEMENTS

```
════════════════════════════════════════════════════════════════
1. Formalize the physics-first design gate as a checklist item

   Pattern:  5 design entries (36% of all) were proxy
             approximations — speed tables, fixed-damping on
             speed-varying plants, distance-for-time, scalar
             curvature collapse. All had an exact physics
             formula available; none was computed.

   Action:   Add a one-question pre-implementation checklist
             to CLAUDE.md / design review:
               "What physical quantity does this parameter
                approximate? Can we compute it directly via
                dimensional analysis or first principles?"
             If yes → derive; if no → document why the proxy
             is acceptable and note the edge cases.

   Impact:   Addresses the single largest source category
             (4 of 9 design bugs). Prevents the class of
             issues most likely to require 3+ fix iterations.

────────────────────────────────────────────────────────────────
2. Add an E2E validation gate for any numeric constant change
   in tuning files

   Pattern:  Entry 13 (mpc_q_lat bundled into feature commit,
             E2E explicitly deferred) cost +82.5 pts across
             4 tracks and required bisection + 3 E2E runs to
             diagnose — the highest single-event deduction in
             the log.

   Action:   Pre-merge rule: any diff that touches
             _MPC_WEIGHT_AUTO_DERIVE_PARAMS,
             config/av_stack_config.yaml tuning keys, or
             numeric literals in control/trajectory layers
             requires an E2E validation record in the commit
             message (min: 60s run, highway_65 + one curve
             track). Enforce via a pre-commit grep hook that
             flags numeric constant diffs without the tag.

   Impact:   Catches the entire "bundled tuning" failure mode
             before merge. Also forces intent documentation
             for every constant change.

────────────────────────────────────────────────────────────────
3. Add a phase-gate assertion to the steering test suite

   Pattern:  3 entries (3, 8, 11) traced to steering terms
             active in phases where they should be zero
             (FF on straights, term_time leaking to global
             path, binary gates on continuous curvature).
             Each required dedicated trace work to isolate.

   Action:   Add a golden-recording replay test that asserts
             each steering term (ff_term, term_time,
             anticipation_term, etc.) is near-zero in frames
             classified as the opposite phase. Wire it into
             the comfort-gate regression tier so it runs on
             every analysis-pipeline change.

   Impact:   Phase-gating bugs currently cost 1–2 iterations
             to detect. A replay assertion catches them
             immediately on commit, at near-zero runtime cost
             (~0.3s alongside existing Synthetic tier tests).
════════════════════════════════════════════════════════════════
```
